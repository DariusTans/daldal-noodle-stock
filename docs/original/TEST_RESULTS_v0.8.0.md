# ผลทดสอบ Daldal v0.8.0

วันที่สรุป: 31 ตุลาคม 2026 · สถานะ: ผ่านการทดสอบอัตโนมัติและตรวจภาพหน้าจอของต้นแบบ

**ยังไม่มีผลทดลองทีมร้าน** ตารางนี้ไม่ใช่การรับรองจากผู้ใช้งานจริง หลายคนข้ามเครื่องและแป้นพิมพ์บนมือถือจริงต้องทดลองแยกตาม UAT_SCRIPT.md

## วิธีทดสอบ

ใช้ Chrome ผ่าน Playwright บน local preview ของ source เดียวกับชุดเผยแพร่ แยก browser context จากข้อมูลผู้ใช้ ทดสอบขนาดคอมพิวเตอร์ 1440×1000/1050 และมือถือ 390×844 รวมพื้นที่ลดเหลือ 390×500 เพื่อดูรายการท้ายกับแถบบันทึก บทบาทในต้นแบบเป็นการจำลอง ไม่ใช่บัญชีจริง

เส้นทางหลัก journey-browser.cjs เริ่มจากทะเบียนตั้งต้น สร้างหน่วยและวัตถุดิบใหม่ผ่านหน้าจอ แล้วทำทุกธุรกรรมผ่าน UI จนออก Dashboard/CSV ไม่ฉีดสถานะสำเร็จระหว่างทาง อ่าน storage เพื่อยืนยันผลเท่านั้น เส้นทางแยกและ regression บางชุดใช้ fixture ตั้งต้นก่อนกดทดสอบกรณีเฉพาะ ไม่ได้นับเป็นหลักฐาน full journey จากศูนย์

ก่อนปรับ UX รันเส้นทางเดียวกันบน v0.7.0 ได้ยอดตรงกัน เก็บผลใน tests/results/v070-baseline.json หลังปรับทดสอบทั้งพนักงานมือถือ–ผู้จัดการคอมพิวเตอร์ และทุกบทบาทขนาดมือถือ

## สิ่งที่ปรับจาก baseline

ก่อนปรับ ผู้ทดสอบต้องกลับเมนูเพื่อต่อจากยืนยันนับไปเคลื่อนไหว จากเสนอซื้อไปเปิดใบซื้อ จากซื้อแล้วไปตรวจรับ และจากใบซื้อไปบันทึกบิล รุ่นนี้มี “ทำต่อ” และงานวันนี้ที่ส่งรหัสต้นทางตรงใบ ทดสอบว่าการเปิดร่างบิลเชื่อมใบซื้อไม่เพิ่ม revision/เอกสาร และช่องยอดเงินยังว่างจนกรอกจากหลักฐาน

หน้าเดิมเปิดผ่าน hash ได้ รายงานเปิดต้นทางตรงใบ หลังบันทึกแล้ว URL เก็บรหัสรายการและตัด action สร้างออก เพื่อไม่เปิดฟอร์มสร้างซ้ำเมื่อ refresh

## Regression และเส้นทางผิดปกติ

| ชุดทดสอบ | ผล / หลักฐานสำคัญ |
|---|---|
| core + browser | ผ่าน CRUD หน่วยซ้ำ บทบาท สำรอง/นำเข้า ข้อมูลเสียไม่เขียนทับ และมือถือ |
| counts + counts-browser | ผ่านร่างค้าง/refresh, 0 ต่างจากว่าง, ส่งกลับแก้ไขพร้อมเหตุผล, ยืนยันล็อก, stale ข้ามแท็บ |
| stock + stock-browser | ผ่านเบิก/ของเสีย/ปรับ/กลับรายการ, ไม่ติดลบ, ตรวจครบหมดอายุเมื่อเปลี่ยนข้อมูล, เสนอซื้อซ้ำ/ล้าสมัย |
| buy + buy-browser | ผ่านชื่อและบทบาทผู้พิจารณา, ส่งกลับ, ราคาแก้ต้องตรวจใหม่, กฎวงเงินเดิม, ซื้อไม่เพิ่ม stock |
| receive + receive-browser | ผ่านรับบางส่วน ของเสียหาย/ไม่รับ ปัญหาค้าง ปิดครบ/ขาด ยืนยันซ้ำไม่เพิ่ม stock ซ้ำ และ cross-tab |
| expense + expense-browser | ผ่านหลักฐานแนบ/แก้/สำรอง/ดาวน์โหลด, ผู้ตรวจไม่ตรงถูกกัน, ส่งกลับ/ยืนยัน/ยกเลิก, confirmed-only totals, cross-tab |
| report + report-browser | ผ่านช่วงวันไทย CSV 5 แบบ ป้องกัน CSV formula, สกุลเงินแยก, ต้นทางตรง, staff ไม่เห็นการเงิน, อ่านไม่แก้ข้อมูล |
| ux-browser | ผ่านยกเลิกออกจากฟอร์มคงข้อมูล, ยืนยันออกทิ้งเฉพาะส่วนไม่บันทึก, เปลี่ยน hash/บทบาทมี guard, save draft/refresh, wizard ย้อนกลับ, ปฏิเสธซื้อผ่าน UI, บิลไม่มีหลักฐาน/สงสัยซ้ำต้องรับรองก่อนยืนยัน |
| evidence-browser | ผ่านแสดงภาพจริงคู่ข้อมูล desktop, สลับ proof/data บนมือถือ, ดาวน์โหลดภาพและ PDF fallback, ซ่อนเหตุผลไม่มีหลักฐานเมื่อมีไฟล์ |
| journey-browser | ผ่านเส้นทางครบวงจร 2 รูปแบบอุปกรณ์ ไม่มี browser page errors |

งานวันนี้คำนวณจากสถานะเดิม ไม่เปลี่ยนข้อมูลเมื่ออ่าน และไม่ให้ manager ทำขั้นผู้พิจารณาที่กำหนดเป็น owner โดยอัตโนมัติ ทดสอบพร้อม UI ปฏิเสธซื้อและกลับสู่รายการเสนอซื้อเดิม

## ข้อจำกัดของผลทดสอบ

- ทดสอบ browser จริงบนคอมพิวเตอร์โดยปรับ viewport ไม่ใช่เครื่อง iPhone/Android จริง การเลื่อน/แป้นพิมพ์/การเข้าถึงต้องทดลองกับอุปกรณ์ร้าน
- PDF มีตัวอย่างและปุ่มดาวน์โหลดเสมอ ทดสอบการดาวน์โหลดเมื่อใช้ไฟล์ที่ตั้งใจไม่ให้ preview สำเร็จ ไม่รับรอง PDF viewer ของทุกเบราว์เซอร์
- ทดสอบ cross-tab ใน browser context เดียว ไม่มีฐานข้อมูลส่วนกลาง จึงไม่อ้างผลส่งต่อข้ามคน/ข้ามเครื่อง
- ไม่ทดสอบบนข้อมูลจริง ไม่อ้างว่าผู้ใช้จริงผ่าน ไม่เพิ่ม AI/OCR ระบบบัญชีจริง หรือ authentication
- การยืนยันเผยแพร่ตรวจจาก Sites; ชุดธุรกรรมทดสอบบน local source ไม่กดสร้างข้อมูลทดสอบบน Site ส่วนตัวของผู้ใช้
